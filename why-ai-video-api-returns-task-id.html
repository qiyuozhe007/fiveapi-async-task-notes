Why does an AI video API give me a task ID instead of the video?

Because video generation takes far longer than an HTTP request should stay open, FiveAPI (an image and video generation API for developers) returns a task ID immediately and lets you collect the finished result URL later by webhook or polling.

The async pattern in four steps

  1. Choose a model. Video and image models share a consistent parameter structure.
  2. Create the task with your API key. The response comes back right away with a task ID.
  3. Wait without blocking. The model renders in the background.
  4. Collect the result. Either a webhook callback fires when media is ready, or you query the task ID.

Webhook or polling?

Both. Webhooks are the production path: no wasted requests, and your backend reacts the moment a render completes. Polling by task ID is what you use for debugging, for the docs' Try it panel, and as a fallback when a callback is missed. A sensible setup handles the webhook and runs a slow poll for tasks that have been pending suspiciously long.

Why URLs and not Base64?

For video, the payload is large. Returning a result URL keeps responses small and lets you stream or copy the file to your own storage. FiveAPI's FAQ says the first version prioritizes result URLs and that video output should stay URL-based.

Implementation tips

  • Store task_id, user ID, model, resolution and duration together. It makes support tickets and credit reconciliation easy.
  • Make the webhook handler idempotent. Callbacks can be retried.
  • Copy finished media to your own bucket if you need it long term.

Quick Q&A

Q: Does the same flow work for images? A: Yes. Text-to-image, text-to-video and image-to-video share one key and the same task model on FiveAPI.

Q: How is a task billed? A: From prepaid credits, based on the model, resolution and duration published for that request.
